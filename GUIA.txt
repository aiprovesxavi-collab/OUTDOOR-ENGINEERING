CÒPIES DE SEGURETAT D'OUTDOOR — GUIA (novembre de 2026)
=======================================================

COM FUNCIONA (TRES PECES)
  · GitHub és el ROBOT: cada nit fa la còpia sol, gratis, des d'un repositori PRIVAT teu.
  · Backblaze és el MAGATZEM: on es guarda la còpia, a Europa, fora de Supabase i fora del teu compte de Google.
  · Les dues FRASES DE XIFRAT són el CADENAT: el robot tanca la còpia abans d'enviar-la; sense les frases no la pot obrir ningú
    (ni Backblaze, ni GitHub, ni nosaltres).
Tu només ho prepares una vegada (uns 30 minuts, seguint els punts 1, 2 i 3) i fas una prova de recuperar-la (punt 4).

QUÈ HI HA EN AQUEST ZIP (6 fitxers, cap carpeta)
  · GUIA.txt                        aquesta guia
  · ROBOT-1-copia-nit.txt           el robot que fa la còpia cada nit
  · ROBOT-2-prova-restauracio.txt   el robot que comprova que la còpia es pot recuperar (punt 4)
  · funcio-avisa-accio.ts, funcio-llegeix-factura.ts, funcio-pregunta-bd.ts
                                    el codi de les tres Edge Functions de Supabase, per si mai cal tornar-les a posar
Tots van al repositori PRIVAT nou (outdoor-copies), MAI al de l'app (el de l'app és públic).

QUÈ FA
Cada nit, a les 2:17, GitHub fa sol una còpia de tot el programa i la guarda fora de Supabase, a Backblaze (Europa, Amsterdam):
  · la base de dades sencera (clients, factures, treballadors, comptabilitat, usuaris…), amb l'eina oficial de Supabase;
  · tots els fitxers (fotos, PDF de factures, nòmines, contractes, documents): només els nous o canviats;
  · el codi de l'app (el repositori de GitHub).
Tot surt xifrat: a Backblaze només hi ha fitxers il·legibles. Per obrir-los calen les dues frases de xifrat, que només tindràs tu.
No s'esborra mai res de la còpia: si un fitxer desapareix de Supabase, a Backblaze hi continua.
Cost: Backblaze regala els primers 10 GB; després, uns 7 $ al mes per cada 1.000 GB (preu de novembre de 2026). Amb les vostres
dades, res o cèntims al mes.

ABANS DE COMENÇAR
Prepara dues FRASES DE XIFRAT llargues (per exemple 6 paraules a l'atzar amb algun número: «teulada9 riu persiana gat17 pluja escala»).
Desa-les al gestor de contrasenyes ARA, i també en paper en un lloc segur. Si es perden, les còpies no es poden obrir mai més.

──────────────────────────────────────────────────────────────────────
1. BACKBLAZE (10 minuts)
──────────────────────────────────────────────────────────────────────
 1. Crea un compte a https://www.backblaze.com → B2 Cloud Storage. EN EL FORMULARI DE REGISTRE tria la regió «EU Central»
    (la regió es tria en crear el compte i no es pot canviar). Activa-hi la verificació en dos passos.
 2. Buckets → Create a Bucket:
      · Bucket Unique Name: outdoor-copies-XXXX (posa-hi 4 lletres o números teus: el nom ha de ser únic al món)
      · Files in Bucket are: Private
      · Default Encryption: Enable
      · Object Lock: Enable → després, a «Object Lock», Default retention: 30 days (així ningú, ni amb les claus, pot esborrar
        res dels últims 30 dies)
 3. Application Keys → Add a New Application Key:
      · Name: copies-github · Allow access to Bucket(s): només el bucket d'abans · Type of Access: Read and Write
    Apunta el keyID i l'applicationKey (l'applicationKey només surt una vegada) al gestor de contrasenyes.

──────────────────────────────────────────────────────────────────────
2. SUPABASE (5 minuts)
──────────────────────────────────────────────────────────────────────
 1. La contrasenya de la base de dades: Project Settings → Database → Reset database password. Fes-ne una NOMÉS DE LLETRES I
    NÚMEROS (sense símbols: si no, cal codificar-los) i llarga (30 caràcters). Desa-la al gestor. (L'app no la fa servir: no canvia res.)
 2. La cadena de connexió: botó «Connect» (a dalt) → Session pooler → copia la URI. Substitueix [YOUR-PASSWORD] per la contrasenya.
    Ha de quedar com: postgresql://postgres.rafgewuvokjldxbyiqai:LACONTRASENYA@aws-0-eu-....pooler.supabase.com:5432/postgres
 3. Els fitxers: Storage → Settings (o Project Settings → Storage) → S3 Connection: activa «Enable connection via S3 protocol».
    Copia l'«Endpoint» i la «Region». A «S3 Access Keys» → New access key → descripció «copies» → copia l'Access key ID i el Secret.

──────────────────────────────────────────────────────────────────────
3. GITHUB (10 minuts)
──────────────────────────────────────────────────────────────────────
 1. Crea un repositori nou: nom «outdoor-copies», i marca PRIVATE (molt important: privat).
 2. Hi poses els fitxers d'aquest zip (no hi ha cap carpeta: la pujada de GitHub no en crea).
      · Els dos robots han d'anar dins la carpeta .github/workflows, i la carpeta es crea escrivint-la al nom del fitxer:
         a) «Add file → Create new file» (si el repositori encara és buit, l'enllaç «creating a new file»).
         b) Al quadre del nom, escriu exactament  .github/workflows/copia-nit.yml  (a cada barra, GitHub converteix el que hi ha
            davant en una carpeta).
         c) Obre ROBOT-1-copia-nit.txt (doble clic: s'obre amb el Bloc de notes), selecciona-ho tot (Ctrl+A), copia (Ctrl+C) i
            enganxa-ho (Ctrl+V) al quadre gran de GitHub.
         d) «Commit changes».
         e) El mateix amb el nom  .github/workflows/prova-restauracio.yml  i el contingut de ROBOT-2-prova-restauracio.txt.
        Si està bé, a la pestanya «Actions» hi surten «Còpia de seguretat (cada nit)» i «Prova de restauració».
      · La resta, amb «Add file → Upload files», tots alhora: aquesta GUIA.txt i els tres funcio-….ts (el codi de les Edge
        Functions, per si mai cal tornar-les a posar).
 3. Settings → Secrets and variables → Actions → New repository secret. Crea aquests 10 (nom exacte, en majúscules):
      SUPABASE_DB_URL        la cadena de connexió del punt 2.2
      SUPABASE_S3_ENDPOINT   l'Endpoint del punt 2.3
      SUPABASE_S3_REGION     la Region del punt 2.3
      SUPABASE_S3_KEY_ID     l'Access key ID del punt 2.3
      SUPABASE_S3_SECRET     el Secret del punt 2.3
      B2_KEY_ID              el keyID de Backblaze
      B2_APP_KEY             l'applicationKey de Backblaze
      B2_BUCKET              el nom del bucket (outdoor-copies-XXXX)
      XIFRAT_FRASE           la primera frase de xifrat
      XIFRAT_SAL             la segona frase de xifrat
 4. Actions → «Còpia de seguretat (cada nit)» → Run workflow. Tarda de 5 a 30 minuts (la primera, més: copia tots els fitxers).
    Ha d'acabar en verd. Si surt vermell, envia'm una captura.
 5. A partir d'ara es fa sol cada nit. Si mai falla, GitHub t'envia un correu.

──────────────────────────────────────────────────────────────────────
4. PROVA DE RESTAURACIÓ (ara una vegada; després, cada 3 mesos)
──────────────────────────────────────────────────────────────────────
Una còpia que no s'ha provat de recuperar no és una còpia. La prova es fa en un projecte de Supabase DE PROVES (el gratuït);
el workflow s'atura sol si per error li dones el projecte de debò.
 1. A Supabase, crea un projecte nou «outdoor-proves» (regió Europa, pla Free). Fes-li també una contrasenya només de lletres i
    números, i copia la seva cadena de connexió (Connect → Session pooler).
 2. Al repositori outdoor-copies, secret nou: SUPABASE_PROVA_DB_URL = aquesta cadena.
    (Si també vols provar els fitxers: activa-hi l'S3 com al punt 2.3 i crea els secrets SUPABASE_PROVA_S3_ENDPOINT,
     SUPABASE_PROVA_S3_REGION, SUPABASE_PROVA_S3_KEY_ID i SUPABASE_PROVA_S3_SECRET.)
 3. Actions → «Prova de restauració» → Run workflow (dia buit = la còpia més recent).
 4. Al resum surt quants clients, llocs, factures, treballadors, usuaris i fitxers hi ha. Han de ser els mateixos que a l'app.
 Quan acabis, pots pausar el projecte de proves (Supabase el pausa sol si no es fa servir).

──────────────────────────────────────────────────────────────────────
5. SI UN DIA CAL RECUPERAR-HO TOT (DESASTRE)
──────────────────────────────────────────────────────────────────────
 · Si només s'ha esborrat o canviat alguna cosa per error, NO cal res d'això: digue-m'ho. Hi ha el registre de canvis i les còpies
   diàries de Supabase (7 dies), i en podem treure només el que calgui.
 · Si s'ha perdut el projecte: crea'n un de nou a Supabase (Europa, pla Pro), posa la seva cadena a SUPABASE_PROVA_DB_URL i fes la
   «Prova de restauració» amb «Copiar també els fitxers». Després caldrà: tornar a posar les Edge Functions (el codi és als fitxers
   funcio-….ts) amb els seus secrets (GEMINI_API_KEY i VAPID_KEYS, que tens al gestor de contrasenyes), la configuració d'Authentication,
   i canviar l'adreça del projecte a l'app (config.js i la política de seguretat de les pàgines): t'ho preparo jo.
